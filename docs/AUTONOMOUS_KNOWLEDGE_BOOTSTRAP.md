# D0 knowledge bootstrap

D0 is an exceptional, dormant-by-default protected-YELLOW lane for reconstructing descriptive, non-enforcing repository knowledge or authority-map artifacts when ordinary A5 semantic review and repair would be self-referential. It never supersedes ordinary GREEN/YELLOW/RED rules, authorizes scientific/runtime work, workflows, credentials, branch protection, repair, or merge.

Activation requires exactly one owner-authored standalone `<!-- knowledge-bootstrap-prestart:{canonical-json} -->` comment. Schema `1` has exactly `schema_version`, `repository`, `issue_number`, `trusted_base_sha`, `authorized_paths`, `purpose`, `a5_mode`, and `scientific_runtime_prohibited`; it must exactly match canonical protected-YELLOW pre-start evidence for repository, issue, base, and paths.

Only explicitly authorized `README.md`, `AGENTS.md`, and eligible descriptive `docs/**` `.md`/`.json` paths qualify. Governance/control-plane, A4--A7, model contracts, workflows, scripts, tests, runtime, and scientific/model paths are excluded. D0 itself is a one-time ordinary protected-YELLOW implementation and cannot bootstrap itself.

After successful exact-head hosted CI and identity/path revalidation, A5 may emit an explicit skip audit before reviewer or repair authority creation. This is not a clean A5 verdict: GPT exact-head holistic review and every protected-YELLOW merge gate remain required. A GPT blocker freezes the work unit; later work needs fresh authorization.
